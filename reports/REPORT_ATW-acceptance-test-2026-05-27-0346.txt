Initial test run on this platform found 3 failures in test_metadata.py
(test_save_and_reload_description, test_save_and_reload_txxx_field,
test_json_roundtrip_preserves_all_fields). Root cause: load_from_file()
called clear() which reset the MetadataManager mode to config.active_mode,
clobbering any prior reload_mode() call. On this machine active_mode =
"Music"; tests expected "Archival Recording" mode fields. Two fixes applied:

  1. metadata.py — load_from_file() now resets field values in-place rather
     than calling clear(), preserving the current mode (_field_specs).

  2. test_metadata.py — test_save_and_reload_txxx_field() given explicit
     reload_mode('Archival Recording') calls on both manager instances,
     making the test machine-independent.

Both fixes are behaviour-neutral on Linux LMDE where active_mode defaults
to "Archival Recording". Fixes committed as be12f13.
